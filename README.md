# 聊天机器人1：QQ 群聊天与答疑

本机 Node.js 应用。NapCat 登录个人 QQ，将 OneBot 11 群消息发送到本工具。支持指定群无需 @ 自动接话、@ 答疑和定时活跃。

## 使用

1. 安装 Node.js 22 或更新版本，下载仓库后双击 `启动答疑机器人.bat`，浏览器打开 <http://127.0.0.1:3210>。服务在后台运行，首次启动会安装依赖。
2. 双击 `安装或启动QQ连接.bat`。组件已安装时会直接启动，服务就绪后在管理页点击「打开 QQ 扫码登录」。原生组件安装在 `%LOCALAPPDATA%/QQGroupQA/engine` 的英文目录中，避免中文路径导致的启动失败。安装器会在缺少组件时下载所需文件。不要运行 `napcat.kill.qq.bat`，它可能结束日常 QQ 进程。
3. 在 NapCat 的网络配置中新建 **WebSocket 客户端（反向 WS）**：地址复制本工具的连接参数，Token 复制本工具的 Token，消息格式选 `array`，启用后保存。默认地址为 `ws://127.0.0.1:3210/onebot/v11/ws`。本工具支持 Universal 单连接，勿配置独立 Event/API 双连接。
4. 配置模型，保存后点击「测试模型」。
5. 填入允许答疑的群号（可以从已登录 QQ 获取群列表），打开「开启机器人」，保存。将该 QQ 加入群后发送 `@机器人 你的问题`。在「自动聊天」独立指定无需 @ 的群并启用。

## WorkBuddy 模型

**只有 WorkBuddy 客户端的用户：选择「WorkBuddy 账号连接」并点击连接。** 此方式调用腾讯官方 npm 包 `@tencent-ai/codebuddy-code` 的 ACP 微信登录流程，打开 CLI 返回的官方授权页面，不需要创建第三方应用。请使用与 WorkBuddy 相同的微信完成登录。客户端登录不会自动变成这里的授权，CLI 与 WorkBuddy 的可用模型及权益也可能不同。登录后可以填写账号支持的模型 ID。

CLI 的凭据由官方软件管理，存储在本项目 `data/codebuddy-auth` 独立目录。机器人不提取桌面客户端凭据，也不返回 OAuth Token。`data/cli-account.json` 仅保存授权完成时间与昵称。答疑通过官方 CLI 的 print 模式调用，禁用内置工具、MCP、Hook、自动记忆和后台任务；工作目录使用独立空目录，不加载个人或项目设置。默认启用「仅免费模型」：每次问答前通过 ACP 创建空会话读取官方模型目录，只接受明确标注 `x0.00 credits` 的模型，标记不明确或转为收费时拒绝调用，不回退到收费模型。未填写模型时选目录中的首个明确免费模型。目录标价由平台控制，不能保证永久免费；关闭免费限制后测试和答疑可能消耗额度。管理页「清除已保存密钥」只清除应用 API Key 与开放平台令牌，不清除官方 CLI 的独立登录配置。

官方依据：[登录方式](https://www.codebuddy.cn/docs/cli/quickstart)、[CLI 命令及工具白名单](https://www.codebuddy.cn/docs/cli/cli-reference)、[无头调用](https://www.codebuddy.ai/docs/cli/headless)。

另外提供两种接入，不含共享账号、内置免费密钥或凭据提取：

- **官方授权**：在 [WorkBuddy 开放平台](https://open.workbuddy.cn/)创建并审核第三方应用。申请 `user.task.readable user.task.invokable`，登记回调地址 `http://127.0.0.1:3210/oauth/callback`，填入 clientId/clientSecret 后点击授权。如果平台不接受本机 HTTP 回调，需要先取得支持的回调部署方案；本工具不会绕过平台限制。使用官方云端任务与 ACP SSE 协议，不调用本地助理 API。官方任务接口未公开指定某个免费模型的参数，模型选择、额度和计费由 WorkBuddy 决定。
- **兼容 API**：如果你已经有 WorkBuddy 转接服务或其他 OpenAI 兼容服务，填写服务提供的地址、Key 和模型 ID。例：地址 `http://127.0.0.1:端口/v1`，程序会请求 `/chat/completions`。也支持直接填写完整 `/chat/completions` 地址。本机接口可不设 Key，远程接口要求 HTTPS。转接服务需自行部署，本项目不包含非公开接口逆向实现。

**WorkBuddy 客户端免费权益不代表公开 API 永久免费。** 官方 CLI 免费模型调用已在开发环境验证；下载项目后需要使用自己的账号重新授权。开放平台云端模式使用模拟服务测试；该模式每轮创建一个独立任务、带入有限历史，可能增加启动延迟及云端任务数量。

官方依据：[应用接入流程](https://open.workbuddy.cn/docs/third-party-app)、[Open API 与 ACP](https://open.workbuddy.cn/docs/openapi)、[NapCat 配置](https://napneko.github.io/config/basic)、[安装发布页](https://github.com/NapNeko/NapCatQQ/releases/tag/v4.18.38)。

## 行为与数据

### 自动聊天

在管理页填写需要自动聊天的群号后启用。新安装默认关闭，群名单为空；其他群保留原 @ 答疑规则。机器人默认名称与自称为「聊天机器人1」，不会更改 QQ 账号资料中的昵称。

- 收到指定群新文字消息后等待 4 秒合并连续发言，持续聊天最多合并 15 秒；每群自动回复至少间隔 90 秒。冷却期的新消息合并等待，不逐条排队。
- 默认参考本群最近 20 条文字消息（含机器人的回复），每条截取 1600 字、总上下文约 8000 字符；各群隔离。30 分钟空闲清理，保存配置、断线、重启或清空记忆时丢弃。不会读取启动前的聊天档案，不识别图片、语音、文件。
- 群聊记录会发送给当前配置的模型用于生成回复，正文不写本机日志或磁盘。自动回复至多 500 字，不发送 @ 段或 CQ 指令。
- 忽略自己发的消息、重复事件、斜杠指令。@ 其他人的消息只加入上下文，不触发自动回复；@ 机器人由答疑通道处理，并撤销待发送的自动接话，避免同一条消息双重回复。
- 机器人正在答疑时延后自动接话；积压超过 5 分钟的旧话题丢弃。失败只记本机状态，不向群里反复发送报错。免费模型限制同样生效。
- 「开启机器人」控制 @ 答疑和自动聊天；定时活跃有独立开关。自动聊天使用独立群名单，不继承「响应所有加入的群」。

### 定时活跃气氛

在管理页「定时活跃」独立配置。此功能有自己的群号名单，**不会继承“所有群答疑”开关**。默认关闭；预设计划为北京时间每天 `09:00、12:00、15:00、18:00、21:00`，填写群号后可启用。

- 混合话题包含日常问候、趣味问题和轻松小游戏，不 @ 任何人、不 @ 全体成员。可以单独选择一种话题类型。
- 默认使用当前模型生成，并沿用现有免费模型限制；模型不可用时使用本地话题。也可关闭 AI，仅用本地话题。
- 默认避让最近 15 分钟内有群成员发言的群，正在答疑时也跳过。生成期间有人开始聊天也跳过。新启动先观察相同时长；这不依赖读取群聊天历史，仅在内存记录新消息时间。
- 每天最多设置 6 个时间点，限制在北京时间 08:00—21:59。服务器内置定时器每 10 秒检查一次，必须保持 Node 服务、QQ 连接和电脑运行；电脑休眠或服务关闭时不能发送。
- 不补发断线、关机期间错过的时间点，也不会在开启或重启时立即补发。长时间生成超过 3 分钟就跳过本次。
- 发送前先写 `data/activity-ledger.json`，重启后仍不会重复发送。发送回执失败时不自动重发，以避免群里出现重复消息。这个取舍可能漏发一次，但不会为追发而刷屏。
- 本地发送记录保留最近 14 天，记录结果、群号和机器人生成的话题，不记录群成员聊天正文。记录损坏时需要修复，不会静默丢弃防重记录。
- 「预览一条话题」使用已保存配置，只在页面显示结果，不向 QQ 群发消息。

### @ 答疑

- 答疑通道处理允许群里 **@ 当前登录账号** 的消息。忽略私聊、自发消息及 @全体成员；自动聊天规则见上方独立说明。
- 白名单为空时不响应任何群，除非明确勾选「响应所有加入的群」。
- 每个群里的每个人拥有独立上下文。最多 20 轮，30 分钟过期；内存总量有上限。重启、保存配置或清空对话会丢弃历史。`@机器人 /重置` 仅清理当前人的当前群历史。
- 最多同时生成 4 条回答；重复消息自动过滤；默认每人 5 秒间隔。同一人上一条未完成时不排队。
- 问题最多 4000 字符，答复最多 8000 字符，长消息分段发送。仅支持文字问答，不读取图片或文件。
- 页面只监听 `127.0.0.1`，不向局域网开放。页面会话、来源检查和 OneBot Token 保护接口。日志不保存提问正文，已知密钥会被替换。
- 密钥和 WorkBuddy OAuth 令牌保存在 `data/config.json`，不在配置读取接口返回、不写入源码仓库。此文件是本机明文敏感配置，不要共享 `data` 目录或连接配置下载文件。
- 群提问和相应对话历史会发送到你选择的模型服务。官方云端任务可能保留记录；清空本机记忆不删除云端记录。
- ACP 工具授权统一取消，客户端不暴露文件、终端或本地 MCP 能力。云端 Agent 的预置行为仍由 WorkBuddy 控制。
- NapCat 是个人 QQ 协议接入方式，可能触发 QQ 风控。建议使用专用账号并遵守平台规则。

## 开发与停止

需要 Node.js 22+，Windows 启动脚本使用 PowerShell；推荐使用 pnpm 安装锁定版本依赖。

```powershell
pnpm install --frozen-lockfile
pnpm test
pnpm start
```

启动脚本优先使用系统 Node.js，也能发现随 Codex 安装的 Node。后台服务日志保存在 `data/service.stdout.log` 与 `data/service.stderr.log`。使用 `停止答疑机器人.bat` 停止；它只核对并结束本工具记录的 Node 监听进程。

仓库不包含任何 QQ 登录状态、模型授权、API Key、群名单、聊天记录、NapCat 二进制或运行日志。`data/`、`runtime/`、`node_modules/` 与本机截图均已加入 Git 忽略规则，下载后需自行完成配置。

自定义端口：在 PowerShell 设置 `$env:PORT = '3211'` 后运行启动脚本；启动与停止必须使用同一端口设置。相应修改 NapCat 的 WS 地址和 OAuth 回调登记。

测试包含真实本机 HTTP/WebSocket 集成链路、消息过滤与隔离、停用后不发送、限流去重、上游错误处理、SSE 跨块解析、ACP 取消工具权限和 OAuth 刷新。模拟测试不会向任何真实 QQ 群发送消息。
